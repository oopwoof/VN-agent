01 — 产品设计

三个入口，一条管线

同一条生成链路暴露成三种控制粒度：把方向盘交给系统、交给用户、或者交给对话。 产出物是一个可编译运行的 Ren'Py 工程，不是一段文本。

ENTRY A

一键 Autopilot

零点击直达：预设解析 → 全链路自动跑 → 首个场景就绪即进入播放器。

resolve_preset(theme) → per-job Settings M0：工作台内按钮，非独立 URL 入口；预设恒为 autopilot_best
ENTRY B

分步工作台

大纲确认 → 剧本生成 → 素材 → 编译。每一步的中间产物都可见、可干预。

03 — 评测机制

七种失效模式，七种判定器

把它们混成一次 LLM 打分，是这类系统最常见的设计错误：模型会用同一种模糊语气回答七个性质不同的问题， 而你分不清它哪一句可信。

#失效模式判定器性质
1 图结构坏了悬空 next_scene_id · 孤儿场景 · 起始缺失 确定性图算法reviewer._structural_check 二元
2 声明与实现不符角色没登场 · 变量没人写 · 伏笔埋了没回收 确定性对账_local_structural_audit · _check_context_deps 二元
3 分支是假的两条路写出几乎一样的内容 路径签名相似度——向下走 3 层，比对白 token、出场角色集合、情绪分布，三者同时相似才判定为装饰性分支_check_branch_divergence · Jaccard 阈值
4 策略没执行标了 accumulate 但张力没有爬升 机械信号与模型分交叉——行序号与「能量」的线性相关，正斜率即爬升strategy_metrics · check_strategy_consistency 连续
5 写作层不行语气不分 · 没有潜台词 · 节奏塌 LLM rubric 五维打分，阈值 3.5reviewer._quality_check 连续
6 玩起来不对这一帧信息不可读 · 走进死路 · 玩家没有能动性 多模态 vision judge，评在合成的代表帧上playtest.vision_judge 连续+分级
7 跑不起或太贵超预算 · 超时 · 吞吐退化 harness 断言 + 健康信号；实时采样花费，超限即熔断smoke_longvn · --max-budget-usd 二元+阈值

04 — 横切设计

三条贯穿全链路的规则

CUT A

不许模型冒充确定性判定

合法类别之外另有一个 LLM 被允许发出的子集。硬图缺陷类别保留给确定性审计， 模型若幻觉出其一，强制降级为 advisory。

为什么：这些类别会触发 Director 重跑。触发昂贵动作的证据，必须来自确定性来源。

_LLM_VALID_CATEGORIES
CUT B

输出不是分数，是「谁该修」

多数质量门只回答通过与否。这里的门回答三选一，划分依据是缺陷归哪个组件管。

为什么：不知道谁该修，重试就是随机游走——一次真跑用三轮全场重写证明了这一点。

routing.decide_retry_target · review_can_writer_fix · output_capped_scenes
CUT C

评审本身要被评审

跨厂商第二评审对同一批场景独立打分，量化分歧而不是宣称一致。

结论的措辞很重要：这不是「验证了一致性」，是「量化了分歧」。

05 — 评审的可靠性

知道评审有多不准，比让它看起来很准重要

0.643Pearson r
44.7%完全一致
87.2%差 ≤ 1 分
3.68 / 3.66Sonnet / GPT-4o 均值

中等相关，不是高一致。完全一致只有 44.7%——所以能说的是量化了分歧，不能说验证了一致性。

但分歧是刻度级的，不是方向级的。差 ≤1 分占 87.2%，两个评审很少一个说好一个说坏。

对产品的直接含义：拿它做二元通过门是稳的；拿它做细粒度排序（比较两个配置差 0.2 分）是不稳的。 对照实验的结论因此只能说「方向一致」，不能说「稳定最优」。

自我偏好：两个评审均值几乎相同，无总体级自我抬高证据。 但这只存在于离线 eval——管线内的 Reviewer 仍是同族自评。

06 — 已知缺口

这套设计还缺什么

主动列出来，因为一个不说边界的评测系统不值得信任。

GAP 1没有人工校准。零条人工标注参照——严格讲只知道两个模型之间分歧多大，不知道它们对不对。这是最大的缺口。
GAP 2生产路径上没有第二评审。跨模型交叉验证只在离线 eval 脚本；管线内的 Reviewer 与 Writer 默认是同一个模型。
GAP 3第 6 层评的是合成帧。字体回退、文本溢出、立绘层级、转场时序——凡是渲染期才出现的问题，这一层测不到。
GAP 4零个真实创作者用过。产品判断全部来自自身作为 VN 读者与创作者的经验，需求侧一个假设都没验证。
